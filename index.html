Work

Uscreen

Product Manager · Current

I lead seller onboarding — the path that takes a creator from signup to their first sale. That covers the activation flow itself and the payments and checkout infrastructure sitting underneath it: what a new seller has to configure before money can move, how much of it can be deferred, and which steps genuinely need a human decision rather than a sensible default.

It’s a problem where product and infrastructure are hard to separate. Shortening onboarding usually means changing what the system requires, not just what the screen asks for.

Building on our own API

To understand what our Headless API actually felt like to build against, I used it — a members-only site for a juggling club, in Next.js, self-hosted behind Caddy. Going through signup, auth and gated content as a developer rather than reading the spec surfaces the gaps that bug reports describe only indirectly. It’s the cheapest research I do.

Approach

Model the domain properly the first time.
Typed columns, real constraints, actual foreign keys. A schema that encodes what a thing is answers questions for years; a bag of untyped JSON defers the work to whoever reads it next, usually under pressure.
Build enough of it to know what you’re asking for.
I’m not the strongest engineer in any room, and I don’t need to be. But having implemented a version myself changes the quality of the conversation — I come with a sharper question instead of a vaguer request.
Software should run on the owner’s terms.
Self-hosted, exportable, documented well enough that someone else could pick it up. Most of what I build outside work is for a niche too small to be worth a business model, which is exactly why it should be free and open.
Credit the source material precisely.
A lot of my projects present someone else’s research. Getting attribution and licensing exactly right isn’t an afterthought to that work — it’s the reason the work is allowed to exist.

Newfoundland Coin Varieties

Live

www.nfldcurrency.ca

A free reference for Newfoundland decimal coin varieties, 1865–1947 — the repunched dates, re‑engraved letters and die changes that separate one striking from another. It covers eight denominations, from the large cents through to the $2 gold.

The research, variety descriptions and photographs are Barry M. Borsellino’s, built up over decades. This site is that work made searchable: I built the pipeline and the site, and continue the project with him.

The hard part is that the source material is photographs and word-processor documents, not a database. A Python pipeline reads 16 GB of Barry’s original photography and 87 research documents, decodes his filename conventions, discards duplicates, and resolves the result into 279 varieties across 63 year studies — each published once its write-up is complete. Every variety page leads with one featured coin and its key diagnostic close-up, with Barry’s own guide lines switchable on and off so you can compare against your own coin under a loupe.

A New Look at Newfoundland Varieties

2015

Before the website there was a book. Barry had decades of variety studies spread across documents and photographs, and no single place they lived together. I helped edit them into one 475‑page reference, which Barry then gave away free to any collector who asked for it.

It was the first version of the same problem the site solves now — someone else’s expertise, scattered, worth more once it’s organised and findable. Editing it is also how I learned the material well enough to build a pipeline over it a decade later.

Wunderkammer

In development

A self-hosted collection manager for any kind of collectible — coins, cards, plants, whatever you keep. The existing options are Windows-only, closed, and built for exactly one category. This one is meant to be free, run on your own hardware, and let your data leave whenever you want.

The interesting constraint is supporting arbitrary collection types without giving up on the database. A collection type is a YAML module; installing one issues real DDL and creates a properly typed PostgreSQL table with its own columns and indexes. No JSONB blob, no entity-attribute-value table. A coin has a year that is an integer and a grade that is constrained to the Sheldon scale, because that’s what it actually is — and modules are just repositories, so anyone can define a category I’d never think of.

It’s also built MCP‑first: every feature is exposed as a tool an AI agent can call, so the API and the agent interface are the same surface rather than one bolted onto the other. Still in development and not yet public — I intend to open-source it once it’s worth someone else’s time to run.
